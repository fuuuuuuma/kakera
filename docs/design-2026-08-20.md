## 1. 何であるか

**AIで生成した素材を、誰でも無料で載せて、誰でも無料で持っていけるプラットフォーム。**
素材はトーンの揃った**シリーズ単位**で並ぶ。

作者が得るのは金銭ではなく、**いいね・ダウンロード数・ランキング掲載・作者ページの実績**。
運営は手数料を取らない。というより、**お金がどこにも動かない**。

対象は **動画編集者とサムネイル制作者の両方**。この2者は「探しているのに見つからない素材」が
ほぼ同じで、どちらも「重ねられる素材」と「揃った背景」で詰まる。

### 立ち位置（競合の実測から）

| | UGCのAI生成物を受け入れるか | 価格 |
|---|---|---|
| Pexels / Unsplash | **禁止** | 無料 |
| Freepik / Adobe Stock | **受け入れる＋ラベル義務** | 有料 |
| ぱくたそ | 受け入れない（自社生成のみ・**AI素材を既に4,180点**） | 無料 |
| Civitai | 受け入れる | 無料＋投げ銭 |

**無料ストックは AI を閉じ、有料ストックは受け入れてラベルを義務化した。**
空いているのは **「無料 × 投稿を受け付ける × AI生成 × 日本語」** のマスだけ。

ぱくたそに無くて KAKERA にあるものは3つ。**誰でも投稿できる / プロンプトを全公開する /
シリーズ＝揃いで配る**。3つ目が一番強い（ぱくたそは1点ずつ作るので揃いの単位を持たない）。

### 訴求で使ってよい言葉・使えない言葉

| | |
|---|---|
| 使える | 「この揃いはここだけ」「トーンを合わせた○点セット」「そのまま重ねられる」 |
| **使えない** | 「独占素材」「ここでしか手に入らない1枚」 |
| **使えない（v2.2 追加）** | **「ただで」「無料」「手数料」「一円も動きません」** — 価格の話を表に置かない |

### 価格の話をサイトの表に置かない（2026-08-21・メンテナ指示）

トップ・シリーズ・かけらの各ページで、**値段ではなく中身を先に言う。**
「ただで置いていく場所」のような言い方は、素材そのものの価値より安さを主語にしてしまう。

- **表で言うのは「そろっている」こと。** 見出しは「そろっている素材は、探さなくていい。」
- 「商用可・クレジット不要・登録不要」は**価格ではなく利用条件**なので表でも言う
- **ライセンス全文と投稿規約には事実として書いてよい。** そこは表ではない

`tests/build-site.test.ts` の「表に出す文言の決まり」が機械で固定している。
禁止語がトップ・シリーズ・かけらに現れたらテストが落ちる。

Higgsfield 規約 §4.4 が「出力はユーザー間で一意とは限らない。他ユーザーが類似または同一の出力を
得る可能性がある」と明記しているため、1点単位の独占は主張できない。
**独占できるのは揃いの構成のほうだけ。**

対象を2者に広げたので、文言の基準は **「動画編集者とサムネイル制作者のための」**。
片方だけを名指しした文言を残さない。

## 2. 無償にしたことで、設計が入れ替わった

これは値付けの変更ではなく、**背負う法律とプラットフォームの難所そのものの入れ替え**。

### 消えたもの

| | 根拠 |
|---|---|
| **取引デジタルプラットフォーム消費者保護法** | 同法は**有償**の役務提供契約・通信販売を要件とする。無償の取引は対象外 |
| **特商法11条の販売業者表示義務** | 通信販売に当たらないため不要 |
| 決済・返金・チャージバック | お金が動かない |
| 売上送金（Stripe Connect 等）・資金決済法の論点 | 同上 |
| インボイス・源泉徴収・出品者の適格請求書 | 同上 |
| 運営手数料の設計・表示 | 手数料を取らない |

### 代わりに来たもの

| | 内容 |
|---|---|
| **情報流通プラットフォーム対処法（情プラ法）** | 2025-04-01 施行。プロバイダ責任制限法の改正。**義務が課されるのは総務大臣が指定する「大規模特定電気通信役務提供者」**で、KAKERA は当面該当しない。ただし削除申出への対応・発信者情報開示の枠組み自体は前提として動く |
| **権利侵害の申立て窓口** | 大規模指定を受けていなくても最初から置く。送信防止措置の判断を求められたときの受け口になる |
| **削除基準の策定・公開** | 大規模指定の義務だが、先に整えておくほうが安い。後から作ると運用実績と食い違う |
| **投稿規約でのライセンス許諾** | 投稿者から KAKERA へ「第三者へ無償で再配布することを許諾する」非独占ライセンスを取る。**これが無いと配れない** |
| **投稿者の権利表明** | 自分が生成した／第三者の権利を侵害しない／実在人物・既存IPを含まない |
| **いいね・ランキングの不正対策** | 金銭が絡まなくなった代わりに、ここが一番の難所になった（後述） |

`要点` — お金をやめたことで**法律の重しはほぼ全部落ちた**が、
**UGC を預かる責任は逆に増えた**。誰でも載せられる以上、載ったものへの窓口は必須になる。

## 3. 用語

- **かけら（Piece）** — 1ファイル。`still`（静止画）/ `loop`（ループ動画）/ `se`（効果音）/ `bgm`
- **シリーズ（Series）** — 同じ光・色温度・画角・質感で作られた 6〜12 のかけらの束
- **トーン宣言** — シリーズが守るべき色・光・画角の定義。機械検品の判定基準にもなる

## 4. 作者への見返り（v2 で作り直した）

### v1 の設計は、既知の失敗と同型だった

**MakerWorld（Bambu Lab の3Dモデル共有）は、v1 とまったく同じ設計で始めて壊している。**

- 旧制度はポイントの配分をほぼ「人気」＝ダウンロード数・印刷数だけで決めた
- 公式の言葉で「**さっと刷れる小物が浮上し、手間をかけた複雑な作品が埋もれた**」
- 修正は ①**複数指標の組み合わせ**に変更 ②**Boost**（人が選ぶ加点・12ポイント）を導入

**「DL数の単独ランキングを報酬にする」は、必ず軽いものが勝つ方向に収束する。**

さらに、KAKERA には**交換できるものが何も無い**。Printables の Prusameters は自社プリンタと、
MakerWorld のポイントは Bambu 製品と交換できる。**KAKERA のいいねは、いいねのままで終わる。**

### 決まっていること（2026-08-20 メンテナ判断）

- **いいねのログインは Google**
- **通報・削除は AI が一次スクリーニング、削除の実行は人間の承認を挟む。**
  情プラ法の枠組みでは削除の判断責任が事業者に残るので、AI だけで完結させない
- **ドメインは確定: サイト `kakera.fuuuuuuma.dev` / 素材 `assets.fuuuuuuma.dev`。追加費用ゼロ。**
  `kakera.app` は既に他者が保有していて取得できなかった（DNS実測）。
  `fuuuuuuma.dev` は既に Cloudflare ゾーンがあるので、サブドメインを足すだけで済んだ。
  確定値は `config/site.json` に置いた（移すときはそこだけ直す）
- **動画は Higgsfield を使わない**（費用）。Grok か無料のオープンウェイト（後述）
- 素材ファイルの置き場は **Cloudflare R2**（有効化の許可済み）

### 4つの通貨

1. **ダウンロード数** — サーバ側で数える。**ダウンロード自体はアカウント不要**
2. **保存数** — Civitai が `Most Collected` を持っている軸。**素材サイトでは「保存」がいいねより
   ずっと強い意図**を表す（編集者は「今すぐ使う」ではなく「今度使う」で保存する）。アカウント必須
3. **いいね** — 押した人が分かる必要があるので**アカウント必須**
4. **作者ページ** — 累計を積み上げる名刺。**ポートフォリオとして外部に見せられる形にする**

### ランキングは1本にしない

**総合順位を1つ作らない。** 軸ごとに別のランキングを出す。

- **ダウンロード / 保存 / いいね** の3レーン
- 期間は **日次・週間・全期間**（Civitai も Day を持っている。**日次があると新規が最短24時間で
  上位に出られる**）
- 別レーンで **「今週の一組」を運営が人手で1つ選ぶ**（MakerWorld の Boost に当たるもの）。
  機械の順位と混ぜない

### 出せる報酬を正直に数える

交換できるものが無い以上、実際に出せるのは2つだけ。**無い報酬をあるように見せない。**

1. 作者ページを**ポートフォリオとして通用する形**にする
2. メンテナのチャンネル・note での**紹介枠**（これは実際に価値がある）

### 不正と埋もれへの対処

| 壊れ方 | 対処 |
|---|---|
| いいね・保存の水増し | **アカウント必須**。1アカウント1シリーズ1回。ダウンロードは登録不要のまま守る |
| DL数の水増し | 同一IP・同一シリーズは**1日1回に丸めて**数える。連打を数えない |
| 新規が永久に埋もれる | **日次ランキング**＋**新着枠の常設**＋**運営が選ぶ枠**の3段構え |
| 大量投稿で棚を埋める | 1作者の同時掲載数に上限（初期値：新着面に同一作者は2枠まで） |
| 軽いものだけが勝つ | **総合順位を作らない。**軸を分け、人が選ぶ枠を別に持つ |

## 5. 初期12シリーズ（計108点・運営投稿ぶん）

投稿開放前に、メンテナの生成物で棚を埋める。空の棚には誰も投稿しない。

### v2.2 で組み直した理由

競合リサーチで **ぱくたそが既に AI素材を4,180点持っている**ことが分かった
（自社生成・登録不要・商用可）。カテゴリはファンタジー / ダンジョン / サイバーパンク /
ゲーム背景 / 部屋 / **光エフェクト** / **テクスチャ背景** / 炎 / ひび割れ / 魔法陣 / 銀河 / 布。

v2 の構成は**抽象テクスチャ系が4つ正面からかぶっていた**（抽象グラデ背景・紙とインクの質感・
光の粒・基板回路）。数で勝てない相手と同じ棚に並べても意味がない。

**ぱくたそが持っていないのは2つ。**

1. **透過素材**。写真ベースなので、そのまま重ねられる素材が薄い
2. **用途が名前になっている素材**。ぱくたそは被写体・世界観で切っている（炎、布、銀河）。
   KAKERA は**編集者とサムネ制作者の作業の場面**で切れる

**透過が作れることは実測で確認済み**（2026-08-21）。`nano_banana_pro` で無地背景に主体を描き、
`remove_background` に通すと 4チャンネルの PNG になり、検品ゲート2（アルファ実在）を通る。
市松の上に置いて目視でも確認した。

### 構成

| # | シリーズ | 主な相手 | 構成 | 透過 |
|---|---|---|---|---|
| 1 | 夜の書斎 | 編集者 | 静止画6 | — |
| 2 | 朝のカフェ卓上 | 編集者 | 静止画8 | — |
| 3 | 都市俯瞰 | 編集者 | 静止画8 | — |
| 4 | **矢印と囲み**（手描き） | 両方 | 静止画12 | **○** |
| 5 | **吹き出しと帯**（テロップの下敷き） | 両方 | 静止画12 | **○** |
| 6 | **強調の記号**（！？・チェック・バツ・キラキラ） | 両方 | 静止画12 | **○** |
| 7 | サムネ背景：驚き・爆発・集中線 | サムネ | 静止画10 | — |
| 8 | **光とフレアの重ね** | 両方 | 静止画10 | **○** |
| 9 | データとグラフの抽象 | 編集者 | 静止画8 | — |
| 10 | 和の質感 | 両方 | 静止画8 | — |
| 11 | **紙とテープの切れ端**（貼り込み用） | 両方 | 静止画10 | **○** |
| 12 | 編集の音 | 編集者 | SE 8＋BGM 4 | — |

**透過は 56点**（v2 の22点から倍以上）。ここが空きマスであり、
「最も探して見つからないのが、そのまま重ねられる素材」という設計の主張と一致する。

外したもの: **抽象グラデ背景12色**・**基板/回路**（ぱくたそのテクスチャ背景・サイバーパンクと
正面からかぶるため）。ループ動画は当面外す（Higgsfield は費用が重く、
Grok と無料オープンウェイトの調査が未着手のため）。

### 透過素材の作り方（実測済みの手順・v2.3 更新）

1. `nano_banana_pro` で **無地の単色背景**に主体だけを描かせる（`aspect_ratio: 1:1`）
2. **`npm run cutout` でローカルに抜く**（`src/inspect/chroma.ts`）
3. 検品ゲート2 が「実際に抜けている」と判定したものだけ棚に出す

**プロンプトには「plain flat solid <色> background」「no text」「no other objects」
「high contrast between the subject and the background」を必ず入れる。**
背景が複雑だと抜きが汚れる。

**背景色は主体の色で選ぶ。** 有色の主体なら白背景で足りるが、
**白い塗りの主体（吹き出し・付箋・紙）は白背景だと抜きが曖昧になる**のでマゼンタにする。

### AI の背景除去ではなくローカルで抜く理由（実測）

同じ1点で `image_background_remover` とローカルのクロマキーを比べた。

| | 結果 |
|---|---|
| 画素の一致率 | **99.75%** |
| 不透明領域の IoU | **98.91%** |
| 見た目 | **ローカルのほうが良い** |

**AI版は輪郭にマゼンタのにじみが残っていた。** ローカル版は `suppressSpill()` で
「観測色 = 主体色 × α + 背景色 × (1−α)」を主体色について解き直しているので、縁が濁らない。

加えて、ローカルなら **34点を1コマンドで処理できる**（API は1点ずつの往復）。
`chromaKey()` は透明になった割合を返すので、**抜けなさすぎ（<15%）と抜けすぎ（>97%）を
機械で拾える**。

### 書き出し比率

- 静止画は長辺 2048px 以上で生成し、`16:9`（1920×1080）/ `9:16` / `1:1` を書き出す
- サムネ用途のかけらは **1280×720 を必ず含める**（YouTube サムネの実寸）
- 透過PNGは元の比率のまま。アルファを保持したまま各比率を作らない（切れるため）

## 6. 生成元の格付け（法務ゲート）

**運営投稿ぶんも、一般投稿ぶんも、格付け A のみを受け付ける。**
判定基準は「出力物を第三者へ再配布・サブライセンスできることが条文で確認できるか」。

| 生成元 | 出力の権利 | 商用 | 第三者への再配布 | 帰属表示 | 格付 | 扱い |
|---|---|---|---|---|---|---|
| **Higgsfield** | 所有権を主張しない（§4.4） | 制限なし | **明示的に可** — 顧客や第三者へ transfer / sublicense できる | 不要 | **A** | 画像・動画 |
| **ACE-Step v1-3.5B** | Apache-2.0 | 無条件で可 | 可 | 不要 | **A** | **BGM（ローカル）** |
| **Stable Audio Open 1.0 / Small** | 「You own any outputs」 | 年商100万USD未満は無料 | 出力配布への制限なし | **出力の配布には不要**（モデル・派生物の配布時のみ） | **A−** | **SE（ローカル）** |
| Grok / xAI | ユーザーが保持 | 可 | 明示なし | **xAI が帰属表示を求める** | B | **動画のみ条件つきで可**（後述） |
| Gemini / Imagen | Google は所有権を主張せず | 可 | 明示なし | 不要だが **SynthID 透かしが常に埋まり無効化できない** | B | 使わない |
| Pika | 所有権を主張しない | 可 | **AI Self の出力は書面同意なしの再配布・収益化を禁止** | 不要 | C | AI Self を使わない条件でのみ |
| **MusicGen / AudioCraft** | — | **重みが CC-BY-NC 4.0 ＝ 商用不可** | — | — | **D** | **使用禁止** |

### 判断の理由

- **MusicGen は罠。** コードは MIT だが**重みが CC-BY-NC 4.0**。音楽生成のローカルモデルで最も有名なぶん、
  最も踏みやすい。**コードのライセンスと重みのライセンスは別**という構造は音声・画像モデル全般にある。
  リポジトリの LICENSE だけ見ると必ず間違える。判定は常に重みの側を見る。
- **Grok と Gemini を外した理由は品質ではない。** Grok は xAI への帰属表示を求め、
  Gemini は SynthID 透かしが必ず入って無効化できない。どちらも**素材を受け取った人に不確実な義務や
  制約を転嫁する**ことになる。素材サイトの商品は「受け取った人が何も考えずに使えること」。
- **Stable Audio Open の訓練データは CC0 / CC BY / CC Sampling+ のみ。** 来歴が追える音源。

### 動画だけ格付け B を条件つきで開ける（2026-08-20 判断）

Higgsfield の動画生成は費用が重いので、動画は **Grok か無料のオープンウェイト**に切り替える。

**Grok を使う場合の条件**（B格のまま、運用でカバーする）:
- xAI が帰属表示を求めているので、**そのかけらのページに「xAI / Grok で生成」を明示する**
- 受け取った編集者に義務を転嫁しないよう、**KAKERA 側が表示を負う**立て付けにする
- xAI は**IP補償を出していない**ので、動画では特に人物・実在物を避ける

**無料のオープンウェイトを使う場合**: BGM の ACE-Step / SE の Stable Audio Open と同じく、
**重みのライセンスを条文で確認してから**格付け表に足す。候補の調査は未着手。
**重みが CC-BY-NC のものは使えない**（MusicGen と同じ罠が動画モデルにもある）。

### 投稿時の扱い

- 投稿フォームで **生成元の申告を必須**にする（サービス名・モデル名）
- 格付け A 以外を選ぶと投稿できない（機械ゲート）
- 申告は自己申告なので嘘をつけるが、**規約違反として削除できる根拠**になるのが目的

### 監視項目（規約は変わる）

1. **Higgsfield §5.1(iii)** — 「Service や Outputs を使って Service と競合する製品・サービスを開発するな」。
   KAKERA の立ち位置を **「配布・流通」** に固定し、サイト上で生成機能を提供しない。規約更新を定点で追う。
2. **Stable Audio Open の年商100万USD条件** — 無償プラットフォームになったので当面到達しないが、
   `generator` フィールドで対象素材を特定できる状態は維持する。

## 7. ライセンス設計

### CC0 を名乗らない

1. **CC0 は「権利を持つ人が放棄する」宣言。** 文化庁「AIと著作権に関する考え方について」（2024-03-15）は、
   AI生成物の著作物性を個別判断とし、①プロンプトの分量・内容 ②生成の試行回数 ③複数生成物からの選択
   の積み重ねで判断するとしている。著作物性が保証されない生成物に CC0 を付けると前提が崩れる。
2. **CC0 は放棄なので「素材そのものの再配布・転売の禁止」を書けない。**

### KAKERA ライセンス（利用規約＝契約として構成する）

- 商用可・クレジット不要・改変可・使用数無制限
- 禁止するのは **素材ファイルそのものの再配布・転売・素材集への収録** のみ

### 投稿規約（投稿者 → KAKERA）

無償でも、KAKERA が第三者へ配る以上、**投稿者からの許諾が要る**。

- 投稿者は KAKERA に対し、**非独占・無償・世界的・再許諾可能**なライセンスを付与する
  （KAKERA 上での配布と、利用者への KAKERA ライセンスでの再許諾のため）
- 投稿者は著作権を手放さない
- 投稿の取り下げは可能。ただし**取り下げ前にダウンロードされた素材のライセンスは存続する**
  （これを書いておかないと、利用者が完成動画を出したあとに権利が消える）

### 同意の成立

単品DLは登録不要なので、同意はブラウズラップになる。
**ダウンロードボタンの直近に**規約リンクと「ダウンロードすると KAKERA ライセンスに同意したものと
みなします」を必ず置く。フッターのリンクだけでは足りない。

## 8. 技術構成

**v2.1 で全面的に Cloudflare へ寄せた。** 根拠は下の「Vercel をやめた理由」。

```
[ブラウザ] ──ページ────────────> Workers Static Assets（kakera.fuuuuuuma.dev）
     │                            ★ リクエストは無料・無制限
     ├──素材ファイル────────────> R2 カスタムドメイン（assets.fuuuuuuma.dev）
     │                            ★ egress 無料 / Class B 月1000万まで無料
     └──いいね / DL計数 / 投稿──> 同じ Worker の API 経路 + D1
                                  ★ ここだけ 10万req/日 を消費する
```

### Vercel をやめた理由（v2.1・公式ドキュメントの実確認）

v2 では「Workers 無料枠の10万req/日は**アカウント全体**の枠なので、ページを Workers に置くと
他のサイトごと Error 1027 で落ちる」としてページを Vercel に置いていた。
**この懸念は静的アセットには当たらなかった。**

> Requests to static assets are free and unlimited.
> — Cloudflare Workers Pricing

つまり**完全に静的へ書き出したページは1リクエストも消費しない**。
消費するのは「いいね」「DL計数」「投稿」の API 経路だけで、これはページビューの数分の1に収まる。

**条件が2つある。守らないと前提が崩れる。**

1. **ページを完全に静的へ書き出す。** SSR にすると Worker が起動して課金対象になる
2. **Workers Cache を有効にしない。** 公式に
   「When caching is enabled, every request to your Worker is charged at the standard Workers
   request rate, **including requests that are normally free: static asset requests**」
   とある。**キャッシュを入れた瞬間に「無料・無制限」が消える**

制限（無料プラン）: 静的アセット **20,000ファイル/バージョン**・個別 **25 MiB**。
12シリーズ108点なら余裕がある。

**得たもの**: 別プロバイダへの往復が消え、DNS も同一ゾーンで完結し、D1 が同じアカウントにある。

### 判断の理由（過去に踏んだ地雷から）

- **素材配信を Workers に通さない。** Workers 無料枠の 10万リクエスト/日は**アカウント全体**の枠で、
  超えると同じアカウントの全サイトが Error 1027 で巻き添え停止する。素材サイトは画像リクエストが
  桁違いなので、ここを通すと他のサイトごと落ちる。R2 の独自ドメイン直配信なら Workers を経由せず、
  Class B 操作は月1000万まで無料。
- **DL計数だけは Workers を通る。** 画像そのものではなく「ダウンロードボタンを押した」信号だけを
  送るので、リクエスト数は画像の1/20以下に収まる。**ビーコンは非同期にし、失敗してもDLは止めない。**
- **Vercel Blob を使わない。** 容量32KB のまま `Billing State: Inactive` によってストアごと停止し、
  アプリが全面ダウンした実績がある。原因は容量ではなく支払い設定。
- **R2 を選ぶ理由は egress 無料。** 在庫ホスト型では転送量課金が無料配布の生死を直接決める。
- **R2 の `r2.dev` 公開URLは本番で使えない。** Cloudflare 公式が
  「rate-limited and should only be used for development purposes」と明言しており、
  **キャッシュも効かない**。素材配信には**カスタムドメインが必須**。
  ここがドメインを避けて通れない唯一の理由。
- **いいね・ランキング・投稿があるので、v0 の「静的JSONだけ」は成立しない。** D1 を最初から入れる。
  ただし**シリーズ本体のカタログは D1 に置き、静的化したJSONをビルド時に吐いて一覧を配る**
  （一覧表示で毎回DBを叩かない）。
- **ページは静的生成。フレームワークを使わない。** カタログが既にこのパッケージで型付き TS なので、
  `catalog.json` を読んで HTML 文字列を返す**純関数**として書ける。純関数なら機械検査できる
  （リンク切れ・コントラスト・JSON-LD の妥当性）。Next.js / Astro を足すと
  ビルド系統がもう1つ増えるだけで、この規模では得るものが無い。
- R2 の単一 PUT は 5GiB 上限。大きい動画・一括ZIP は multipart にする。

## 9. データモデル

```
Series   id, slug, title, description, tone,
         audience: ["editor" | "thumbnail"],
         creator_id, license, status,
         aiGenerated: true,                       ← 常に true。画面とファイルのメタに出す
         generator { service, model, version },   ← 必須・格付けAのみ
         prompt_public, version, created_at, published_at,
         like_count, download_count, save_count   ← 集計値をキャッシュ

Piece    id, series_id, kind (still | loop | se | bgm),
         file { r2_key, bytes, mime, sha256 },
         variants [{ ratio, w, h, r2_key }],
         prompt, seed, negative_prompt,
         alpha, duration_ms, loop_seamless, bpm, key,
         use_tags [], download_count,
         depictsPerson: false                     ← 人物を含むか。投稿では常に false を要求

Creator  id, handle, display_name, avatar, bio, links[],
         total_likes, total_downloads, series_count

Like     creator_id(押した人), series_id, created_at   ← 一意制約で1回に固定
Save     creator_id, series_id, created_at            ← 同上。いいねより強い意図シグナル
DlEvent  series_id, piece_id, day, ip_hash            ← (series_id, day, ip_hash) で一意
Report   target_type, target_id, reason, contact, status, created_at  ← 権利侵害の申立て
Pick     series_id, week, note                        ← 運営が人手で選ぶ「今週の一組」
```

- `price_jpy` / `invoice_no` / `legal_name` / `address` は**削除**（無償になったため不要）
- `Like` / `Save` / `DlEvent` の一意制約が、そのまま不正対策の実体
- `Report` を最初から持つ。**窓口はテーブルが無いと運用が続かない**
- `Pick` は機械の順位と混ぜない別レーン（MakerWorld の Boost に当たるもの）
- **一覧の取得は cursor 方式**にする（offset ではない）。Civitai も `nextCursor` を返している。
  カタログが増え続ける前提なら最初からこう作る
- `depictsPerson` は Civitai の `poi`（person of interest）から借りた。
  **人物を扱わないと決めていても、拒否するには「人物かどうか」を持つ必要がある**

## 10. 生成・検品パイプライン（運営投稿ぶん）

`tools/generate/series/<slug>.json` にシリーズ定義（トーン宣言＋各かけらのプロンプト）を書き、
生成 → 機械検品 → R2 アップロード → カタログ登録。
定義ファイルがそのまま**出所の証明**と**創作的寄与の記録**になる。

### 機械検品ゲート（通らないものは棚に出さない）

1. 解像度・アスペクト比が宣言通りか
2. 透過PNG に**実際にアルファチャンネルがあるか**
3. ループ動画の先頭フレームと末尾フレームの差分が閾値以下か（シームレス判定）
4. 音源の無音区間・0dBFS 張り付き検査
5. **同一シリーズ内の色ヒストグラム距離**でトーンの揃いを機械判定
6. `generator` が格付け A のものだけか（**法務ゲート・自動**）
7. **プロンプトの禁止語検査**（後述・**v2 で追加**）

5 が肝。「トーンが揃っている」が売り文句である以上、目視ではなく数字で裏を取る。

**ただし色距離には限界がある（実素材で確認）。** night-desk の6点を生成して測ったところ、
距離 0.4318 と 0.4088 の2点は目で見て全く問題なく揃っており、
逆に距離 0.3043 の1点が「寝室」で**意味的に外れていた**。
**色ヒストグラム距離が測れるのは色調だけで、「これは書斎か」は測れない。**
機械ゲートは色調の外れ値を拾う道具であって、シリーズの一貫性の保証ではない。
**目視の確認を省略できるとは考えない。**
6 も自動にする。人が覚えている前提にしない。

一般投稿にも 1・2・6・7 は同じゲートを通す（3・4・5 は警告のみ）。

### ゲート7: プロンプトの禁止語検査（v2 で追加）

**Adobe Stock の投稿規約が、出来上がった絵ではなくプロンプトの段階で線を引いている。**

> アーティスト名・実在の著名人・架空のキャラクター・場所・財産に言及するプロンプトで作った作品は、
> 法的権利がある場合を除き提出できない

**KAKERA はプロンプトを全公開する設計なので、この規約を機械で検査できる。**
禁止語の辞書（著名アーティスト名・キャラクター名・実在人物名・ブランド名）と突き合わせ、
プロンプトに含まれていたら投稿を止める。

これは設計 v1 が見落としていた、**プロンプト公開の2つ目の意味**。
差別化のためだけでなく、**モデレーションの道具になる**。

## 11. 画面

**白基調・ゴシック体。**

- **トップ** — シリーズのカード。1カードに**シリーズ内4点をタイル表示**して「揃い」が一目で
  伝わるようにする（単品サムネの海にしない）。各カードにいいね数とDL数
- **ランキング** — 週間DL・週間いいね・全期間。**新着枠を別に常設**して新規が埋もれないようにする
- **シリーズページ** — 全かけらを並べる。**masonry にしない。**
  均一の高さのセルに実比率の枠を描き、比率を等幅で明記する
  （編集者もサムネ制作者も「16:9 か 9:16 か」で捨てるため）
- **かけら詳細** — プレビュー・DL・**プロンプト**・生成モデル・ライセンス
- **作者ページ** — 累計いいね・累計DL・シリーズ一覧。**ここが報酬の受け皿**
- **音** — 波形＋再生。BGM は BPM 表示
- **絞り込み** — 対象（編集／サムネ）と用途タグ
- **投稿** — 生成元の申告と権利表明への同意を必須にしたフォーム
- **通報** — 各シリーズページに常設。フッターにも権利侵害の申立て窓口

### Google 画像検索の構造化データ（v2 で追加・設計 v1 に無かった穴）

**無料素材サイトの流入は Google 画像検索が主戦場なのに、v1 には一言も入っていなかった。**

各かけらのページに `schema.org/ImageObject` の JSON-LD を出す。
`license` / `acquireLicensePage` / `creator` / `creditText` / `copyrightNotice` を入れると、
Google 画像検索に **「Licensable」バッジ**が付き、ライセンスのフィルタにも入る。

**正確に書いておく**: Google は「**構造化データは検索順位に影響しない**」と明言している。
効くのはバッジとフィルタへの露出であって、順位ではない。
それでも**実装コストがほぼゼロなので、やらない理由が無い**。

### AI生成であることのラベル（v2 で追加）

全かけらに `aiGenerated: true` を持たせ、**画面とファイルのメタデータの両方**に出す。

理由は業界の標準がそこに固まりつつあるから。
**Freepik は `_ai_generated` タグを義務化**（違反はアカウント処分）、
**Adobe Stock はメタデータのチェックボックスを必須化**、
**EU AI Act 第50条が 2026-08-02 施行**（透かしの実装は 2026-12-02 まで猶予）、
Google が Search / Chrome / Gemini で **C2PA の検証を展開中**。

**法的な整理**（断定は避ける）: 第50条の「出力を機械可読に標識せよ」は
**AIシステムの提供者**（Higgsfield 等）の義務で、配布するだけの KAKERA が提供者に当たる読み方は苦しい。
別に**利用者（deployer）としての開示義務**があり、対象は「実在の人物・物・場所・出来事に酷似し、
本物と誤認させる」ディープフェイク。**KAKERA は人物を扱わず、本物と誤認させる絵を出さない方針なので、
ここに触れない立て付けにできる。**

### デザインの決め（白基調ゴシック）

- 地は白。面を重ねず、**黒の細い罫線と余白で構造を作る**。影は使わない
- 見出しは太いゴシック。**数字（いいね・DL・順位）は大きく等幅で出す** — これがこのサイトの通貨だから
- 差し色は**青1色**に絞る。素材サムネが色とりどりなので、UI側が色を持つと喧嘩する
- **いいねだけ例外でローズ**。押した／押していないが一目で分かる必要があるため

### プロンプト同梱

全シリーズでプロンプトを公開する。有料が無くなったので**非公開にする理由がなくなった**。
むしろプロンプトが見えることが、このサイトに来る理由のひとつになる。
